The architecture — and the exact life of one question

Two views make up "the architecture": the structural view (what the components are and how they connect) and the behavioral view (what actually happens, function by function, when a clinician asks a question). Part 1 is the structure; Part 2 traces one Review-mode question end-to-end with file/line references; Part 3 covers the Deep-Learning branch; Parts 4–6 catalog the guardrails, data stores, and model routing.

Part 2 · Behavioral view — the life of one Review question

Everything below is traced from the current code. The bird's-eye route:

Browser submitQuestion() ─POST /ask→ clarify gate ─(job)→ run_question() thread
  → semantic cache? hit → done ($0)  |  miss ↓
  → intent router (Haiku) → build_evidence_base_with_progress()
     → local pgvector RAG (≥20 hits → skip network)  |  else live PubMed, 7 tiers × N terms
     → score · provenance adjustments · quality threshold · PRISMA dedup · outliers · currency
  → ask_clinical_question() (Opus, 8K tokens) → validate_evidence_mapping() ─fail→ 1 retry
  → persist (history · query_cache · citation audit) → job complete

Phase A — In the browser

STEP 1 · submit

submitQuestion() (index.html:3965) reads the question and active mode and POSTs JSON to /ask: {question, mode, context, skip_clarify}. context is empty on first submission.

Phase B — Clarify gate Haiku

STEP 2 · /ask handler

(app.py:187) If no context was provided, generate_clarifying_questions() (endo_ai.py:469, model structured_fast = Haiku) decides whether key clinical facts are missing (tooth, vitality, age…). If it returns questions, the API responds {needs_clarification, questions} — no job is started. The UI shows the clarify modal; the user's answers are appended as "Additional clinical context provided by the clinician:" and re-POSTed with skip_clarify=true. Any router error fails open — the pipeline proceeds.

Phase C — Job creation & polling

STEP 3 · async job

create_job() mints a job_id; a daemon threading.Thread runs run_question(); the API returns the id immediately. The browser's pollStatus() (index.html:4108) polls GET /status/<job_id> for {progress, message, status} ticks. Two safety details:

  • Abort: POST /abort/<job_id> sets a flag; every long phase checks is_aborted() and bails cleanly.
  • Bulk abstract text is not shipped to the client: _safe_papers() (app.py:266) strips abstract text from the status payload, so a completed job returns metadata for ~100 papers (PMID, title, authors, year, journal, score, provenance) rather than 100 abstracts. Single abstracts are served on demand when the clinician clicks a citation (Step 13) — that is how every reference manager works, and it is what makes a claim checkable. This is a bulk-transfer boundary, not a prohibition.

Phase D — Cache & intent triage

STEP 4 · semantic cache pgvector

(app.py:296) The cache key is "[mode] question". get_cached_answer() (rag.py:385) embeds the key with MiniLM (384-dim; input window now 2,000 chars after the truncation fix) and runs a cosine search over the query_cache table. A hit needs similarity ≥ 0.92; Deep-Learning entries also must be ≤ 7 days old (curricula go stale), Review entries have no TTL. On a hit the job completes instantly with the stored answer + papers at $0.00.

STEP 5 · intent router Haiku

classify_question_intent() (endo_ai.py:1900, ~200 output tokens) triages the question into kind (simple / standard / complex), retrieval (local / pubmed / both) and needs_clarify, and its one-line reason is surfaced in the progress bar ("Routing as clinical question…"). It fails open to the full pipeline.

Phase E — Building the evidence base

STEP 6 · smart search terms Haiku

(app.py:400 build_evidence_base_with_progress()) First generate_search_terms() (endo_ai.py:847) distills the clinical question into a tight PubMed-style topic string (e.g. "vital pulp therapy MTA Biodentine permanent teeth outcomes").

STEP 7 · RAG-first: the local library pgvector

If library_stats() shows ≥ 50 papers, rag_search(smart_topic, limit=100) embeds the topic and runs cosine KNN over the 1,886-paper endo_papers_rag table (ivfflat index). If ≥ 20 papers come back:

  • rag_results_to_scored() converts rows to scored-paper dicts;
  • papers are banded into evidence tiers by score (≥70 → cochrane/level1 buckets, 50–70 → level2/level3, <50 → level4/level5);
  • apply_currency_tags() → detect_outliers() → flag_superseded_by_review() run, the _summary block is built, and the pipeline skips the network entirely. Typical progress jumps 15% → 75% here.
STEP 8 · live PubMed fallback — 7 tiers × N query angles NCBI

If the library is thin, generate_multi_search_terms() (endo_ai.py:511, Haiku) produces several complementary query phrasings, then the engine walks the tier ladder — Cochrane (via fetch_cochrane(), PubMed fallback), then Level I → V — calling fetch_papers() (endo_ai.py:1163) per tier per term with cross-tier PMID dedup. Inside each fetch_papers() call:

  • esearch — query = (topic) AND (tier filter) AND endo-domain filter NOT "Retracted Publication", retmax=50, sorted by relevance, 20-s timeout. Malformed PMIDs are regex-rejected, and every call is written to pubmed_audit.jsonl (query, ids, HTTP status, latency) — provable provenance that every PMID Claude sees came from a real NCBI response at a known timestamp.
  • efetch + esummary — full abstract text plus metadata (year, citation count, journal, authors).
  • _parse_efetch_batch() splits the batch into per-PMID {title, abstract}, used three ways: (1) bulk_cache_abstracts() persists them to the Postgres abstract_cache; (2) per-paper extract_sample_size() / extract_followup_period() regex extraction (the fixed metadata-broadcast bug — each paper is parsed against its own abstract only); (3) building Claude's context from kept papers only.
  • classify_coi() — reads PubMed's <CoiStatement>, the authors' own declaration, and returns a tri-state: declared_conflict / declared_none / no_statement. Only a declared conflict is penalised (15%). Negation is evaluated per sentence, because real declarations open with boilerplate and then disclose. A conflict requires a named commercial entity in a non-negated sentence — a manufacturer named in the methods ("files (Dentsply Maillefer)") is a product mention, not a conflict, and public grants or academic editorial roles are not industry conflicts.
  • _merge_corrections_and_registries() — one efetch-XML pass adds the remaining provenance signals: corrections/expressions of concern, retraction notices, MEDLINE indexing status, and trial-registry accessions (DataBankList).
  • detect_preregistration() — design-gated to Cochrane/L1/L2. Trial registration comes from DataBankList, which PubMed populates from the article's own registration, so a review citing its included trials' registry numbers cannot be mistaken for a registered study; PROSPERO+CRD free text covers systematic reviews.
  • score_paper() grades each paper 0–100: study design 39% · sample size 17% (n≥200 highest … n<20 lowest) · recency 17% (≤3 yr highest, classics exempt) · citation velocity 16% (citations/yr with a 2-yr grace period) · follow-up 11%. Journal impact factor is excluded (USE_IMPACT_FACTOR, default off) — PRISMA and Cochrane both advise against screening by journal; the IF is still looked up and displayed as reference metadata only, and the remaining five factors renormalise to 100.
  • Provenance adjustments on top: declared COI ×0.85 · pre-registered ×1.05 · correction ×0.97 · retraction ×0.50 · not MEDLINE-indexed ×0.97.
  • _apply_quality_threshold() — floor 50, keep ≥3, cap 25 per tier, mode-aware (Review biases Tiers I–III; Learn admits more Tier V).
  • The tier's annotated context block is assembled: one metadata header line per kept paper (PMID, authors, year, citations, n, follow-up, IF, score) followed by its own abstract.
STEP 9 · evidence post-processing
  • apply_currency_tags() — papers older than the currency threshold get is_old.
  • detect_outliers() — statistical outliers among scores are flagged, not deleted.
  • flag_superseded_by_review() — PRISMA-style dedup: primary studies published before the newest systematic review's search-cutoff are flagged as already-synthesised so the model cites the SR, not the primaries.
  • evidence["_summary"] is built: total scored, average score, all_scored (sorted), and build_synthesis_order() — the strict tier order the writer must follow.

Phase F — Synthesis & the anti-hallucination gate

STEP 10 · Opus writes the answer Opus · 8K tokens

ask_clinical_question() (endo_ai.py:1983) builds the context via _build_evidence_context() (tiers in strict Cochrane→L5 order, per-tier key-paper panel, COI warning banner) and calls claude-opus-4-7 (reasoning_heavy — deliberately the strongest model; this is the most user-visible quality path). The system prompt enforces:

  • Citation format law — every inline claim marker must be exactly [[PMID:12345678]]; the REFERENCES list alone uses [PMID: N]. Anything else fails to render as a verifiable pill.
  • Strict tier hierarchy — a high-scoring lower-tier paper can never override higher-tier findings; scores only rank within a tier.
  • Contradiction surfacing — if top SRs/RCTs disagree, the answer must open with "The literature is currently divided on this topic."
  • Fixed output structure — ## CLINICAL RECOMMENDATION (2–4 sentences, no citations) → ## EVIDENCE SUMMARY (paragraphs per level, authors inline) → ## REFERENCES (numbered, with journal/IF/n/follow-up/score).
  • Never fabricate PMIDs; flag conflicts, short follow-up, underpowered samples; never end with a question.
STEP 11 · validate → retry → warn guardrail

validate_evidence_mapping() (endo_ai.py:1765) — the product's thesis, now locked by a 51-test suite:

  • Fabrication check — every cited [[PMID:N]] must exist in the evidence base (union of tier ids, tier scored lists, and _summary.all_scored). One invented PMID = automatic fail (−30 pts each).
  • Unattributed-claim detection — regex claim patterns (percentages, p-values, n=, dosages/concentrations, "superior to", "is recommended"…) find clinical claims lacking markers; more than 3 = fail. Exempt sections: Clinical Recommendation, Assessment, Key Takeaways, References, Summary.
  • Gap sections — a substantive section (≥80 chars) with zero markers; >50% of sections = fail.

On failure, _build_corrective_message() names the exact offending PMIDs/sentences and demands a rewrite — one retry (Opus again), then the better of the two attempts wins. If neither passes, a visible ⚠ VALIDATION WARNING banner is prepended telling the clinician to verify before acting. Every attempt is logged to evidence_mapping.jsonl; every model call's token usage and dollar cost goes to the cost log via log_llm_call() (surfaced at /admin/costs).

Non-numeric markers (e.g. [[PMID:AAE-PS-obturation]]) are judged by evidence-base membership like any other citation — the hand-ingested AAE/ESE position statements legitimately carry synthetic identifiers, so a blanket "non-numeric = fabricated" rule would flag every valid citation to them.

STEP 11b · does the source actually say it? Haiku guardrail

verify_citation_support() — Step 11 proves a cited paper is real and retrieved; it cannot tell whether that paper supports the claim. This second gate pairs each claim sentence with the cited abstract and asks a cheap model whether the abstract supports, partially supports, or does not support it. Unsupported pairs get a visible ⚠ CITATION-SUPPORT CHECK block naming the specific claims to verify. Fail-open and advisory — it annotates, never blocks — and catches the real-but-irrelevant citation that a set-difference check is blind to.

Phase G — Persistence

STEP 12 · save everything
  • save_answer() → history (sidebar + Profile).
  • save_query_cache() → embedding + answer + papers into query_cache (future ≥0.92 hits are free).
  • write_citation_audit() → JSONL audit of every cited PMID for the run.
  • The job flips to complete with {answer, papers, cost_usd} (intent-router cost included).

Phase H — Rendering in the browser

STEP 13 · verifiable answer UI

pollStatus() sees complete and hands the markdown to renderAnswer() (index.html:4316): headings/lists/tables are converted to HTML, and every [[PMID:N]] becomes a clickable author-style citation ("Author et al., J Endod. 2024;50(3):123-30" — all authors when three or fewer, first author plus "et al." beyond). Clicking one calls /api/abstract/<pmid> — served from the Postgres abstract_cache populated during retrieval, falling back to a live efetch — so the clinician can read the actual abstract behind any claim without leaving the answer. The bibliography panel lists the scored papers (metadata only), and the export bar can turn the answer into slides, audio, or video.

Part 5 · Data stores & caches

Neon Postgres (pgvector)

  • endo_papers_rag — 1,886 papers · vector(384) MiniLM embeddings · ivfflat cosine index · metadata (year, journal, IF, n, follow-up, level, score).
  • query_cache — semantic answer cache · hit at cosine ≥ 0.92 · 7-day TTL for learn mode · precision-deletable via /cache/clear (≥0.99).
  • abstract_cache — PMID-keyed abstracts, populated as a side-effect of every live fetch; powers the citation popovers and the claim-support check.
  • Provenance columns on endo_papers_rag: coi_status / coi_flag / coi_funder, registry, has_erratum, has_retraction, medline_indexed, is_curated. COI is decided once at backfill time and the stored score carries the penalty — the read path never re-scans, so it cannot double-count, and because RAG ranks on score × 0.6 + similarity × 40 the penalty affects retrieval order, not just the badge.
  • Current library: 1,886 papers — level1 506 · level3 375 · classic 272 · level4 172 · level2 153 · level3a 149 · level5 131 · cochrane 126 · 2 unlabelled. COI: 1,269 no statement · 614 declared none · 3 declared conflict. 69 pre-registered · 265 not MEDLINE-indexed · 16 retracted (excluded from search).
  • Access via a shared ThreadedConnectionPool (transparent proxy; keepalives for Neon).

Known limitations

Stated plainly, because each one changes how much weight an answer can carry.

  • Reasoning is abstract-only. Neither the synthesis nor the claim-support check ever sees methods sections, results tables, or full text — only abstracts. Abstracts report headline numbers, so a success rate or confidence interval in an answer is the figure the authors chose to summarise, not one read from the results. Verify numerical claims against the source before acting on them.
  • Two databases. Cochrane and PubMed/MEDLINE only — no Embase, Scopus or Web of Science. The evidence base is therefore narrower than a formal systematic review, and the tool should not be described as PRISMA-compliant.
  • Fail-open guardrails. The clarify gate, intent router and claim-support check degrade to "not run" rather than blocking an answer. Every answer states which checks actually ran.
  • Retrieval relevance is tuned, not proven. The library-vs-live decision uses a similarity floor that has not yet been calibrated against a labelled question set.
  • Single-process jobs. Answers are generated on in-process daemon threads: a restart loses in-flight jobs, and the app does not scale past one worker as written.
  • Admin routes are unauthenticated. /admin/costs, /cache/clear and DELETE /learn_history/<file> assume a trusted single-user deployment.
